Read the room
before you walk in.

A research crew that sweeps the last 30 days of news about the company or person you're about to meet — through Tavily, models behind the Bifrost gateway — and hands you a one-page brief where every claim is traced to a source the crew actually fetched.

Doorknock02 / 10

The meeting is tomorrow. The research takes an hour you don't have.

  • Scattered. Preparing for an important meeting means digging through news, launches, leadership changes, funding announcements — spread across a dozen sources.
  • Slow. Manual research eats the morning before the meeting; most people walk in under-read.
  • Untrustworthy. Off-the-shelf AI summaries are fluent and often fabricated — invented launches, invented hires, presented with total confidence.
Problem statement 05 — the ask

“An AI-powered research agent that takes a company or person and a meeting time, produces a one-page briefing covering developments from the previous 30 days — news, launches, hires — with sources for factual claims, open questions, and verified findings distinguished from uncertain information.”

Tavily: research. Bifrost: model gateway. Doorknock is that agent, built for the statement, not adapted to it.

Doorknock04 / 10

Four agents. One is not a model.

AgentJob
SCOUT · researchDerives 4–6 queries from the meeting context; runs the Tavily sweep — topic: newsdays: 30depth: advanced — plus one evergreen identity query. The transcript is sealed here.
CLERK · synthesisClusters hits into distinct developments — launches, hires, funding, partnerships — each citing exact transcript URLs, each flagged in-window or background.
SCRIBE · draftingWrites the one-page brief for the meeting at hand; must carry the Clerk's source URLs forward unaltered.
AUDITOR · verificationDeterministic code, zero model calls. Every development must trace to a URL in the sealed transcript. Untraced claim → REJECT → redraft → still failing → repair: stripped to the uncertain — treat with caution section, kept visible.

Agents propose, code disposes. The entire run streams live — every query, hit count, verdict and rejection is on screen as it happens.

Doorknock05 / 10

The gate: hallucination insurance in ~100 lines of code

  • Ground truth is sealed before drafting. The Scout's fetched-URL set is the only allowed citation set. The drafting agents cannot add to it.
  • Claim → source check. Each development needs ≥1 transcript URL (hash- and slash-normalized).
  • Grounding score = traced ÷ total; threshold 0.8. Below → REJECT with a machine-readable report naming each offending claim.
  • Never silent. One redraft; if it still fails, untraceable items move to a flagged uncertain section — verified findings stay distinguishable, exactly as the statement asks.
  • Fully tested. 8 deterministic unit tests — fabricated URL, unsourced claim, out-of-window flag, URL normalization, threshold math, repair semantics. No network, no keys, no models.

Doorknock06 / 10

Bifrost — the only door to the models

Every model call in Doorknock — planning, synthesis, drafting — routes through the Bifrost gateway. The application holds no provider key and cannot reach any model directly.

Request path 
  app (Next.js, AI SDK)
      │  OpenAI-compatible, one base URL
      ▼
  ┌─────────────────────────────────┐
  │  BIFROST GATEWAY v2.5           │
  │  · provider routing: nebius     │
  │  · virtual-key governance       │
  │  · provider key never leaves   │
  └───────────────┬─────────────────┘
                  ▼
   Nebius · NVIDIA Nemotron 3
   open models (nvidia/nemotron-3-super-120b-a12b)
  • Governance in action: a Bifrost virtual key scopes the app to the nebius provider and an explicit model allowlist — the gateway enforces least privilege, not decoration.
  • Drop-in: Bifrost speaks OpenAI-compatible; switching Doorknock from a direct provider to the gateway was one base-URL env var — zero code changes.
  • Deploy shape: runs as a private Docker service (Render) with persistent config disk; the app provisions it idempotently at boot (scripts/bootstrap-bifrost.mjs).
Doorknock07 / 10

Tavily — the research layer, visible end to end

  • The 30-day window is a first-class parameter: topic: "news" + days: 30 on every news query — the recency contract of the problem statement, enforced by the search API itself.
  • Query derivation, not one search: Scout generates 4–6 subject-specific queries (funding, launches, hires, partnerships…), plus an evergreen identity query for background.
  • Nothing hidden: every query, hit count and source URL renders live in the run feed and in the finished brief's research trail. Tavily isn't a black box inside the agent — it's the visible spine.
  • The transcript is the ground truth: URLs enter the audit set only via Tavily results — which is what makes the gate's source-tracing meaningful.
